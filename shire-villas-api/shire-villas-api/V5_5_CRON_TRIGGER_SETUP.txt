SHIRE VILLAS AI REVENUE OS - V5.5 CRON TRIGGER ARCHITECTURE

WHY THIS FIX
The main Shire service defaults to SQLite:
    sqlite:///./shire_villas.db

A second Railway service gets its own filesystem/database.
Therefore the cron worker should NOT run Buyer/NRI/Broker logic directly.

NEW ARCHITECTURE
Railway Cron (stellar-motivation)
    -> trigger_daily_bots.py
    -> HTTPS POST main Shire API /bots/start/daily-suite
    -> main Shire service runs Buyer + NRI + Partner bots
    -> same Tavily/Groq settings
    -> same SQLite database
    -> same Organic Pipeline / Bot Run History
    -> cron exits immediately

CRON SERVICE NEEDS ONLY:
SHIRE_API_URL=https://shire-leads-api-production.up.railway.app
TEAM_API_KEY=<same TEAM_API_KEY used by main Shire service>

REMOVE FROM CRON SERVICE:
TAVILY_API_KEY
GROQ_API_KEY
GROQ_MODEL
LEAD_BOT_PROVIDER
LEAD_BOT_MIN_SCORE
LEAD_BOT_MAX_RESULTS_PER_QUERY
LEAD_BOT_TIME_RANGE
DATABASE_URL

RAILWAY CONFIG FILE:
/shire-villas-api/railway-cron.toml

IMPORTANT:
Pre-deploy Command must be blank in stellar-motivation Settings.
